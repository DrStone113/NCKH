Công thức hiện tại

BMI = weightKg / heightM²

BMR male   = 10w + 6.25h - 5a + 5
BMR female = 10w + 6.25h - 5a - 161

TDEE = BMR × activityFactor
activityFactor = 1.2 / 1.375 / 1.55 / 1.725 / 1.9

Flutter calorie target:
lose     = TDEE - 500
gain     = TDEE + 300
maintain = TDEE

Body fat male   = 1.2×BMI + 0.23×age - 16.2
Body fat female = 1.2×BMI + 0.23×age - 5.4

Water target = weightKg × 0.033 litres

Nguồn: user_model.dart.

  • Flutter dùng BMI normal dưới 25; backend prompt dùng cutoff châu Á dưới 23.
  • Comment gọi body-fat là US Navy nhưng implementation không phải US Navy formula.
  • Flutter và TDEE tool không đặt sàn 1.200 kcal; planner chỉ đặt sàn khi sinh schedule từng ngày.
  • Protein target khác nhau giữa system prompt và phase logic của planner.
  • Không có target carbohydrate hoặc fat.

6. Phân tích AI / Chatbot

User message
 → ChatbotScreen._sendMessage()
 → AIChatProvider.sendMessage()
 → WS /chat/stream
 → ChatGateway
 → MemoryService + turn classification + SystemPrompt
 → Orchestrator
 → OpenAI-compatible LLM + server/client tools
 → thought/token/tool/done/error events
 → AIChatProvider
 → Chatbot UI + structured action cards

Model, prompt và context

  • LLMClient dùng AsyncOpenAI với light/heavy models trong cấu hình.
  • System prompt kết hợp profile, calculated metrics, remaining calories, recent history, rolling summary, confirmed facts, RAG chunks, safety và tool rules.
  • Memory gồm recent messages, summary, full-text relevant history, user facts và RAG.
  • Streaming và native function calling thực sự được sử dụng.
  • Structured response/action items được lưu cùng chat messages.
  • UI hiển thị cả thoughts, làm tăng rủi ro privacy/safety.

Tools

Server tools tính TDEE, search nutrition, suggest dish/workout, tạo/đọc/update plan, query RAG và web medical knowledge. Client tools đọc profile/logs, ghi meal/exercise/weight/lifestyle/reminder, hoàn thành plan item và điều hướng Flutter.

Retry, token và error handling

  • LLM thử primary hai lần rồi fallback hai lần, với delay cố định.
  • Không thấy xử lý riêng HTTP 429, Retry-After, quota hoặc circuit breaker.
  • Không có tokenizer-based context budget, explicit max tokens hoặc cost tracking.
  • App-state orchestrator cấu hình 6 steps/15s nhưng WebSocket router dựng instance mặc định 3 steps/5s.
  • Các turn WebSocket đồng thời có thể interleave do mỗi message tạo một async task riêng.

Security và integrity

  • Backend không xác minh Firebase token; client-supplied user_id/session_id có thể tạo cross-user access.
  • Có database URL và fallback JWT secret không an toàn trong config; giá trị secret không được ghi trong báo cáo.
  • Startup logging có thể ghi đầy đủ database URL kèm password.
  • log_exercise có thể xác nhận thành công dù Firestore thất bại.
  • Lifestyle/reminder tools có thể báo thành công khi provider/persistence không khả dụng.
  • log_weight không cập nhật current profile weight, làm TDEE về sau stale.

Age, gender, height, weight, activity, goal, BMI/BMR/TDEE và daily meal/exercise logs thực sự được đưa vào prompt/planner. Memory còn có thể trích goal, preference và allergy từ chat.

Tuy nhiên, allergy/disease/preferences không có form chuẩn; REST plan truyền restrictions rỗng; user facts có thể auto-confirm nhưng không có UI review; không có feedback/rating/reward/outcome model. test_adaptive_learning.py chỉ là simulator trong test, không phải production implementation.

Phân loại: Level 3 — User profile + recommendation logic + LLM. Có long-term memory nhưng chưa có feedback-driven adaptation để đạt Level 4.

8. Phân tích Meal / Nutrition System

Nguồn dữ liệu

  • 526 thực phẩm Việt Nam.
  • 90 món Việt.
  • 11 nutrition records tổng quát.
  • 10 exercise records cũ và 885 Wger records.
  • Flutter có catalog fallback hard-code; Open Food Facts widget chưa được dùng runtime.

Meal calculation và planner

FoodItem lưu nutrition theo 100 g và scale deterministic theo serving. MealModel cộng calories, protein, carbohydrate và fat.

  1. Planner tính TDEE/calorie target.
  2. Chia ba bữa 30%/40%/30%.
  3. Gọi suggest_dish.
  4. Scale từng thành phần trong giới hạn khoảng 0.65–1.60.
  5. Tính lại nutrition từ catalog.
  6. Tạo exercise schedule và lưu plan/items trong PostgreSQL.

Plan chính không phải LLM tự bịa calorie; nó do tools/dataset/rules sinh. LLM điều phối và diễn giải.

Constraints và verification

Dish tool chỉ hỗ trợ tập hẹp gồm vegetarian, vegan, low-carb, high-protein và no-seafood. Không có allergy ontology hoặc arbitrary allergen enforcement. REST plan hiện bỏ restrictions.

Không có independent verifier sau LLM. Structured dish output được Flutter tin trực tiếp. Fallback estimator có nhánh chỉnh calories mà không scale tương ứng macros, nên có thể mất nhất quán.

History, favorites và search

  • Meal history nằm trong Firestore.
  • Saved meal templates nằm trong SharedPreferences; không có favorite entity riêng.
  • Một search function chỉ tìm catalog hard-code, không tìm toàn bộ dataset đã load.
  • Plan meal được merge vào state nhưng không tự biến thành Firestore diary.
  • Toggle plan meal có thể swallow lỗi và vẫn cập nhật UI.

9. RAG / Knowledge Base

Project có RAG thực sự, không chỉ chèn context thủ công.

Offline JSON + eligible web knowledge
 → chunking
 → BAAI/bge-m3 embeddings (1024 dimensions)
 → PostgreSQL knowledge_chunks + pgvector
 → cosine vector search + PostgreSQL FTS
 → weighted reciprocal-rank fusion
 → MemoryService
 → system prompt with source URLs
 → LLM
  • Dense weight 1.0, keyword weight 0.7, RRF k=60.
  • RAG được gọi tự động cho lượt không phải chitchat và có explicit query tool.
  • Web knowledge dùng PubMed/NCBI và allowlisted search với trust tiers/provenance.
  • Loader có lỗi: insert khai báo năm cột nhưng chỉ có bốn SQL placeholders trong load_dataset.py.
  • Embedding docstring nói normalized nhưng encode không bật normalize_embeddings=True.
  • Retrieval threshold không được áp dụng nhất quán với keyword-only hits.
  • Chưa có recall@k, MRR, faithfulness hoặc citation benchmark.
Corpus thực tế đã được nạp thành công hay chưa: Không xác định được từ code hiện tại.

PROJECT HANDOFF FOR SCHOLAR GPT

Project

Flutter app theo dõi dinh dưỡng, sức khỏe và vận động, kết hợp AI chatbot để trả lời câu hỏi, ghi nhật ký bằng hội thoại và tạo kế hoạch ăn uống/tập luyện cá nhân hóa. Hiện tại đây là health tracker đa nguồn dữ liệu có LLM agent làm lớp hội thoại và điều phối tools; chưa phải hệ thống tư vấn y khoa hoặc adaptive nutrition đã được đánh giá khoa học.

Tech Stack

  • Flutter/Dart, Provider/ChangeNotifier; Android, Web, Windows.
  • Firebase Authentication, Cloud Firestore và SharedPreferences.
  • FastAPI REST/WebSocket; PostgreSQL, async SQLAlchemy, raw SQL, pgvector.
  • OpenAI-compatible chat models; BAAI/bge-m3 embeddings.
  • Wger, Open Food Facts, PubMed/NCBI và allowlisted web search.
  • Docker Compose, Nginx và Cloudflare Tunnel.

Current Architecture

Flutter screens
 → Provider/ChangeNotifier
    ├── Firebase Auth/Firestore
    ├── SharedPreferences/local JSON
    └── FastAPI REST/WebSocket
         → ChatGateway
         → Memory + RAG + System Prompt
         → Orchestrator
         → LLM + tools
         → PostgreSQL/pgvector

Flutter chưa có repository/domain layer đồng nhất. Backend agent được chia thành LLM client, prompt builder, memory, RAG, planner, registry và orchestrator.

Implemented Features

Firebase auth, dashboard, profile/goals, BMI/BMR/TDEE, meal diary, saved meals, exercise catalog/tracking/history, workout simulation, weight/water history, streaming chatbot, server/client tools, action cards, chat history, deterministic long-term plans, plan completion, memory và hybrid RAG code.

Partially Implemented Features

Health onboarding, long-term plan restrictions/atomicity, allergies/diseases, lifestyle loading, real reminders, proactive check-ins, weight/profile synchronization, RAG ingestion, Open Food Facts UI và adaptive replanning.

Current User Data

Id, email, name, age, gender, height, current/target weight, activity level, health goal, body metrics, water, meals/macros, exercises, lifestyle data, reminders, chat history, memory facts và plan completion. Không có structured allergies, diseases, medications, pregnancy, preferences, disliked foods, budget hoặc exercise frequency.

Current Nutrition Logic

BMI = kg/m². BMR dùng Mifflin–St Jeor. TDEE dùng activity multipliers 1.2–1.9. Flutter dùng TDEE−500 cho giảm, +300 cho tăng. Water = 0.033 L/kg. Backend có calorie floor/protein rules nhưng không nhất quán giữa prompt, tool và planner. Không có carb/fat targets.

Current AI Architecture

Chatbot gửi profile/daily logs qua WebSocket tới ChatGateway. Backend tải history, summary, facts và RAG, dựng system prompt, rồi Orchestrator gọi OpenAI-compatible LLM và tools. Response được stream thành thoughts/tokens/actions. Không có token budget, dedicated rate-limit policy, moderation pass hoặc deterministic output safety validation. Backend chưa xác thực Firebase token.

Current Personalization

Level 3. Profile, calculated metrics và daily logs đi vào prompt/planner; memory giữ facts. Chưa có feedback-driven adaptation, reward hoặc measured-outcome learning.

Current Meal Recommendation

Planner tính calorie target, chia ba bữa 30/40/30, dùng deterministic dish tool để chọn/scale món Việt và tạo exercise schedule. LLM điều phối/diễn giải. Constraints chỉ hỗ trợ tập hẹp; arbitrary allergies không được bảo đảm. Không có independent nutrition verifier sau LLM.

Current RAG

Hybrid RAG dùng BAAI/bge-m3, PostgreSQL FTS, pgvector và weighted reciprocal-rank fusion. RAG được tự động dùng cho non-chitchat và có query tool. Dataset loader có lỗi SQL columns/placeholders; corpus thật đã được nạp hay chưa: Không xác định được từ code hiện tại.

Current Safety Mechanisms

System prompt cấm diagnosis/prescription, extreme diet và khuyên cấp cứu ở một số dấu hiệu. Pregnancy, diabetes, kidney/cardio disease và eating disorder được nhắc. Không có moderation, medical validator, medication checker, allergy ontology, pediatric rules, post-generation safety pass hoặc clinical disclaimer rõ. Provider safety: Không xác định được từ code hiện tại.

Current Database

Firestore lưu profiles, body metrics, meal/exercise/water/lifestyle logs và reminders. SharedPreferences lưu saved meals/check-in settings. PostgreSQL/pgvector lưu chat, thoughts, structured data, summaries, facts, tool invocations, knowledge embeddings, plans/items và Wger-related data. Không có Firestore security rules trong repo.

Major Problems

  1. Backend APIs thiếu authentication và ownership enforcement.
  2. Client-controlled user/session identity gây cross-user risk.
  3. Exercise tool có thể báo success khi persistence thất bại.
  4. Database credential có thể bị log.
  5. RAG loader có lỗi SQL placeholders.
  6. Plan creation không atomic.
  7. Allergy/disease/medication safety không enforce.
  8. Lifestyle state không được load ở runtime.
  9. Hai nguồn water và weight/profile synchronization không nhất quán.
  10. BMI/calorie/protein logic khác nhau giữa client/prompt/planner.
  11. Concurrent WebSocket turns có thể interleave.
  12. Thoughts/reasoning được lưu và hiển thị.
  13. Proactive check-in chưa persistent hoặc thực thi logging đầy đủ.
  14. Thiếu live AI/RAG/safety/integration evaluation.

Research-Relevant Existing Components

Vietnamese datasets, deterministic health/meal tools, tool-grounded planner, streaming agent, structured actions, hybrid RAG, conversation summaries/facts, daily context, plan/check-in schema, property tests và Flutter tracking UI.

Missing Research Components

Curated/versioned corpus, working reproducible ingestion, ground truth, retrieval/generation/personalization metrics, baseline and ablation experiments, adherence feedback, adaptive learning, expert safety review, red-team dataset, backend security và model/prompt/dataset versioning.

Final Assessment

  1. Bài toán hiện tại: theo dõi health/nutrition/exercise và dùng chat để truy vấn, ghi log, tạo plan.
  2. Vai trò AI: lớp hội thoại/orchestrator; calculations đáng tin cậy hơn được giao cho tools/datasets/planner/RAG.
  3. Personalization: Level 3, chưa adaptive Level 4.
  4. Giá trị kỹ thuật nhất: streaming agent + tool calling + deterministic planner + memory + hybrid RAG.
  5. Yếu nhất: backend security/ownership và safety assurance, sau đó là action/persistence integrity.
  6. Sẵn sàng nghiên cứu: đủ làm prototype/baseline, chưa đủ đưa ra kết luận khoa học đáng tin cậy.
  7. Còn thiếu: verified corpus/ingestion, evaluation datasets/protocols, baselines/ablations, feedback loop, expert safety evaluation, backend security và reproducibility.
